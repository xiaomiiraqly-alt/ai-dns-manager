# Security and reliability audit — 2026-11-18

Scope: repository `ai-dns-manager` at v0.4, with focused review of `catalogue.py`, `service_scan.py`, `selection.py`, `manager.py`, the DNS forwarder, deployment model and existing automated tests. This document distinguishes confirmed defects from deployment risks. **No production readiness claim.**

## Confirmed defects fixed in PR #3

| ID | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| AUD-001 | High | A resolver returning more than the sampled A records could be classified as service-capable even though additional returned addresses were not probed. Clients could receive an unverified address. | Incomplete coverage is ineligible, including after authorized probes; explicit `PARTIAL_ADDRESS_COVERAGE` verdict. |
| AUD-002 | Medium | The plan stability counter accumulated observations across different proposed targets (A, B, A), so a switch could occur without consecutive confirmation of the same target. | Track target per service; reset counter when the proposed target changes. |
| AUD-003 | Medium | An unavailable required-service scan did not clear previous switch-confirmation counters. | Reset counters and targets on incomplete plans. |

Regression tests are in `tests/test_audit_regressions.py`. CI must pass before merging.

## Operational risks and remaining work

1. **Real API eligibility is unproven.** An invalid-key response can establish that an authentication gate is reachable but not that authenticated generation works. Gemini previously returned `FAILED_PRECONDITION: User location is not supported for the API use` on a tested relay. No automated test proves that this restriction has been resolved.
2. **Incomplete DNS coverage vs performance.** The audited scan now samples up to sixteen A records. Providers returning more than sixteen fail closed. Measure worst-case latency and consider a bounded complete-sampling strategy before production use; do not weaken evidence requirements silently.
3. **Scan scale.** Up to 512 candidate endpoints × 44 starter profiles is more than 22,000 candidate-service combinations, before multiple A-record probes. A 300-second round budget can expire. The implementation uses bounded workers and timeouts, but needs measured capacity tests and adaptive staged filtering on the real VPS.
4. **Monitoring granularity.** Runtime upstream failover measures DNS health. The service-aware controller periodically tests HTTP/API entrypoints, but it is not a guarantee of sustained authenticated model operation or browser usability. WebSocket, login, image/video/audio jobs and account/model permissions are outside the current evidence.
5. **Third-party trust.** Provider lists are untrusted metadata. A correctly validated TLS certificate protects the hostname but does not make a Smart DNS operator trustworthy or guarantee account eligibility. Credentials must remain opt-in and provider-allowlisted.
6. **IPv6/HTTPS hints.** The service-aware pool suppresses AAAA/HTTPS/SVCB for monitored domains because only IPv4 paths are checked. This may affect clients or modern service behavior; verify each client and any DNS-over-HTTPS/browser override before deployment.
7. **Fail-closed expiry.** If scans fail long enough for the active plan TTL to expire, monitored AI domains return SERVFAIL. This is intentional but operationally disruptive; monitor and alert before expiration.
8. **State consistency.** The controller writes a proposed and active plan to disk and swaps in-memory pools. Filesystem failure, process interruption and restart recovery require fault-injection tests and explicit backup/restore verification.
9. **Docker/VPN topology.** The pilot publishes loopback port 5353 only. It is not reachable from AWG clients without deliberate service networking, ACLs and return routes. Existing AWG server uses `amnezia-dns-net` 172.29.172.0/24, with tunnel interface in its container. No change to those networks is made here.
10. **Rollback limits.** The installer has tests for managed-container ownership and simulated rollback. A real Docker failure, interrupted process or corrupt volume/config has not been exercised on the user's VPS. A rollback attempt is not proof of successful recovery.
11. **Observability.** Logs classify failures but lack an operational dashboard, structured metrics endpoint, alerts, latency SLOs, long-duration load tests and persistent per-service history. Sensitive query bodies and keys should not be logged.
12. **Source updates.** Provider feeds are fetched over verified HTTPS and validated with cached fallback, but source authenticity, ownership changes, stale IPs and poisoning of third-party metadata require operational controls. Prefer pinned/reviewed source revisions for sensitive deployments.
13. **Test limitations.** GitHub Actions exercises Python versions, local mock network endpoints and Docker smoke tests. It does not reproduce the actual dual-VPS AmneziaWG routing or run a paid authenticated Gemini generation from the target egress IP.
14. **Service inventory.** 44 starter profiles are extensible but not exhaustive. A website loading is not equivalent to a complete neural-network service working. New API providers require explicit adapters and evidence definitions.

## Deployment gate

Before enabling DNS for VPN clients, require all of:

- GitHub Actions green for the exact pinned commit and offline regressions.
- On-server `manager validate` and `manager scan`, with a reviewed `proposed-plan.json` and no missing required services.
- A real API generation test for each service whose minimum evidence is `generation`, using only approved providers, credentials and eligible regions.
- Local-only Docker pilot health checks on UDP and TCP, then measured response correctness against independent baselines.
- One isolated test AWG client with verified ingress, egress, DNS route, IPv4/IPv6 behavior, no DNS leaks, and reliable rollback.
- Firewall and service ACL review; no public recursive DNS endpoint.
- Monitoring for scan failures, plan expiry, routing switches, resource pressure and loss of VPN connectivity.
- Restore drill: stop service, restore previous DNS on test client, verify original AWG operation.

**Status:** code review and automated tests only; production deployment and end-to-end authenticated AI access remain unverified.
